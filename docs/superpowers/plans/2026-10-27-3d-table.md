# 3D Table Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An optional 3D table for matches (WebGL room, table, lit mat, 3D cards, Wardens, piles, crystals, 3D effects) over the unchanged 2D gameplay DOM, default 2D.

**Architecture:** A WebGL scene (Three.js) renders behind the match. The on-table part of the match DOM (both hero areas, both battlefield rows, draw piles) is moved into a fixed-size `.table-plane` that is placed onto the WebGL mat with a CSS `matrix3d` computed from the same camera every frame (the CSS3DRenderer formula, applied to a React-owned element). Browser hit testing follows 3D transforms, so drag/drop/targeting/fx keep working. From Task 2 on, WebGL draws the units/Wardens/piles/crystals and the DOM on the plane becomes invisible hit targets. Hand, End turn, sidebar and overlays stay in screen space.

**Tech Stack:** TypeScript, React, Zustand, Three.js 0.160, Vitest (+ jsdom), CSS.

**Spec:** `docs/superpowers/specs/2026-10-27-3d-table-design.md` (mockup: `.superpowers/brainstorm/4983-1793131802/content/board-table.html`)

## Global Constraints

- Default view is 2D for everyone; 3D is turned on in Settings ("3D table") or by the 2D/3D button in a match; stored per device in `useSettings` (localStorage).
- 3D never starts in performance mode, with reduced motion, without WebGL; phones (`max-height: 520px` or touch-only + portrait) start in 2D even if 3D is on, with a notice.
- Three.js is loaded only when 3D is on in a match (lazy import, shared `three` chunk).
- No change to engine or game rules; `matchStore` only gets presentation additions.
- Camera: tilt 0.62 rad, FOV 32°, framing the mat plus hand margin; wheel / pinch zoom 1–3× towards the pointer, drag-pan only with the middle button or while zoomed with Space held (left drag stays for cards/attacks); double-click empty table resets.
- Every task ships: `npx vitest run` green, `npm run build`, browser check in 2D and 3D, patch notes en + cs, push to `main`.
- All player-facing text through `t()` with Czech entries.

## Review Focus

- A card dragged from the hand and dropped on a unit / Warden on the tilted plane plays on that target (hit testing through `matrix3d`) → browser check in Task 1, Step 6.
- The attack arrow starts at the attacker's projected centre and the drop resolves the unit under the pointer → browser check in Task 1.
- Resize / fullscreen / sidebar width change keeps the plane on the mat (camera and CSS matrix recomputed on resize) → test of the matrix helper with two viewport sizes, and browser check.
- Switching 2D ↔ 3D mid-match keeps selection, drag state and the hand → browser check.
- Co-op (three rows) still fits the plane → browser check with a co-op match.
